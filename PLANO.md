## 4. Stack técnica

| Camada | Escolha | Justificativa |
|---|---|---|
| Framework | **Astro 5 + TypeScript strict** | Site de conteúdo estático: zero JS por padrão → Core Web Vitals perfeitos (fator de ranking onde TODOS os concorrentes são fracos). Content Collections com schema Zod = conteúdo type-safe (build quebra se um post sair sem title/description/categoria). |
| Conteúdo | **MDX via Content Collections** | Posts em arquivos versionados, frontmatter validado por Zod. Sem CMS = sem custo, sem manutenção. |
| Estilo | **Tailwind CSS 4** | Produtividade + consistência. |
| Deploy | **Vercel** (ou Cloudflare Pages) | Grátis, CDN global, preview por branch, Web Analytics incluso. |
| Analytics | **GA4 + Google Search Console + Vercel Analytics** | GSC é a ferramenta central de SEO; GA4 mede conversão (clique no WhatsApp como evento). Sentry seria over-engineering para site estático. |
| Testes | Zod nos schemas de conteúdo (build-time) + teste de metadados (title ≤60ch, meta 140-155ch, JSON-LD válido) + verificação de links internos + **Lighthouse CI** no pipeline | Automatiza a qualidade de SEO — nenhuma página sai fora do padrão. |

Justificativa Astro vs Next.js: não há nada dinâmico (sem login, sem API, sem banco). Next.js seria capacidade ociosa; Astro é o KISS correto e ainda entrega as vantagens de type-safety via Content Collections.

### Estrutura de pastas
```
src/
├── content/
│   ├── blog/                 # posts .mdx
│   └── config.ts             # schemas Zod (blog, serviços, FAQs)
├── components/               # Header, Footer, CTA-WhatsApp, FAQ, PostCard, Schema
├── layouts/                  # BaseLayout (SEO head), PostLayout (Article schema, autor box)
├── pages/                    # rotas (home, serviços, blog, ...)
├── lib/                      # seo.ts (builders de JSON-LD tipados), constants.ts (NAP, WhatsApp)
└── styles/
```
Regra de ouro: **NAP, telefone e link do WhatsApp vivem em `lib/constants.ts`** — um único lugar, consistência garantida em 100% das páginas.

- Breadcrumbs visíveis + schema nos posts e páginas de serviço.
- RSS feed do blog (LLMs e agregadores consomem).

## 6. GEO — otimização para buscadores de IA (ChatGPT, Perplexity, Gemini, AI Overviews)

1. **Resposta direta no primeiro parágrafo** de toda página/post: a definição citável vem antes de qualquer narrativa. LLMs extraem o trecho mais claro e autocontido.
2. **Frase de entidade padronizada** repetida no rodapé/autor box: "Julia Dias Tozato é psicóloga e neuropsicóloga (CRP XX/XXXXX) que atende em Santos-SP e online" — consistência de entidade é o que faz o modelo "saber" quem ela é.
3. **Headings em formato de pergunta** (H2: "Quanto tempo dura uma avaliação neuropsicológica?") com resposta objetiva de 2-4 frases logo abaixo.
4. **FAQs com schema em todas as páginas de serviço** — o formato mais extraído por AI Overviews.
5. **`llms.txt`** na raiz com resumo estruturado do site (quem, o quê, onde, contato).
6. **Consistência da entidade fora do site**: mesmo nome, mesma descrição, mesmo telefone em Google Business Profile, Doctoralia, MundoPsicologos, BoaConsulta, Instagram, LinkedIn. Os LLMs citam diretórios — Doctoralia foi o 1º resultado na busca por neuropsicóloga em Santos; a Julia precisa estar lá com perfil completo.
7. **Autor box com credenciais em todo post** (nome + CRP + link para /sobre) — E-E-A-T legível por máquina via schema `author` → `Person`.
8. Dados, números e listas estruturadas nos posts (LLMs preferem citar conteúdo com fatos específicos).
